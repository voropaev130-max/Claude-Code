# Redis Security Fix — Скрипты

Решение проблемы из BSI/Hetzner abuse-report (IP 95.216.76.51, Redis 7.4.8 открыт наружу).

## Порядок действий

### 1. Диагностика — где живёт Redis

Зайдите в Proxmox Web Shell на узле (или `ssh root@95.216.76.51`), затем:

```bash
# Скачать со своей машины или скопировать через буфер Web Shell
bash diagnose-redis.sh
```

Скрипт **только читает**, ничего не меняет. Пришлите вывод — поймём, где именно открытый Redis (хост / LXC / VM / Docker).

### 2. Быстро закрыть наружу — фаервол хоста

Если нужно немедленно закрыть порт снаружи (не разбираясь, кто его открыл):

```bash
sudo bash fix-redis-firewall.sh
```

Делает: `iptables DROP` для 6379/6380 на `vmbr0`, разрешает доступ из приватных сетей, сохраняет правила через `iptables-persistent`.

### 3. Правильно настроить сам Redis

Внутри VM/LXC/Docker, где работает Redis:

```bash
sudo bash secure-redis-config.sh
# или с конкретным паролем:
sudo REDIS_PASS='мой_пароль' bash secure-redis-config.sh
```

Делает:
- `bind 127.0.0.1 ::1`
- `protected-mode yes`
- `requirepass <strong>`
- `rename-command CONFIG/FLUSHALL/EVAL/...` → пусто (защита от популярных RCE)
- Бэкап `redis.conf` рядом с оригиналом
- Перезапуск сервиса

## Проверка после фикса

С любого внешнего хоста (НЕ с самого 95.216.76.51):

```bash
nc -zv 95.216.76.51 6379
# Должно: Connection refused / timed out
```

Изнутри сервера должно работать:

```bash
redis-cli -a 'ваш_пароль' ping
# PONG
```

## Если BSI снова пришлёт уведомление

Проверьте дату в отчёте. Уведомления идут пакетами — те, что были до фикса, могут прилететь позже. Главное — чтобы timestamp в новых отчётах был ДО момента фикса. Если позже — фикс не сработал, надо разбираться повторно.
